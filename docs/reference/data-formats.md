# Data Formats

File formats used throughout the project.

## GeoJSON

**Format:** `application/geo+json`, `FeatureCollection` of `Point` (hotspots)
or `Polygon`/`MultiPolygon` (commune context) features.

**Files (all under `public/data/`):**

- `firms-france-faible.geojson`, `firms-france-moderee.geojson`,
  `firms-france-forte.geojson` — live 5-day window, bucketed by FRP intensity
  (see [config-schema.md](./config-schema.md) for the thresholds)
- `communes-context.geojson` — commune boundaries with a hotspot count, for
  communes with at least one current detection
- `archive/YYYY-MM-DD.geojson` — one file per archived day (up to 90 days)
- `archive/index.json` — plain JSON (not GeoJSON), `{ "dates": [...] }` list
  of archived dates available to the time slider

**Hotspot feature structure (approximate — see `csvToGeoJSON()` in
`scripts/fetch-firms.mjs` for the authoritative mapping):**

```json
{
  "type": "Feature",
  "geometry": {
    "type": "Point",
    "coordinates": [2.35, 46.6]
  },
  "properties": {
    "brightness": 320.5,
    "frp": 12.4,
    "acq_date": "2026-07-20",
    "acq_time": "1430",
    "confidence": "n",
    "satellite": "N",
    "commune": "...",
    "commune_code": "...",
    "departement": "...",
    "region": "..."
  }
}
```

## Cache and index files

### `data/commune-cache.json`

Reverse-geocoding cache, keyed by rounded coordinates, with a 30-day
retention. Not deployed to the built site — used only during
`npm run fetch-firms`.

### `data/sources.json.example`

Example/template for the `geopages-template` scaffold's dataset-driven config
generation (`scripts/generate-config.py`). Not used by this project's actual
config, which is hand-written in `src/config.ts` — kept only as a leftover
reference. See [npm-scripts.md](./npm-scripts.md#unused-leftovers).

## Configuration

### `src/config.ts`

TypeScript, hand-written `leaflet-atlas` config — see
[config-schema.md](./config-schema.md).

### `.env.local` (not committed)

```
VITE_BASE_PATH=/your-path/
```

Only relevant for overriding the deployment base path locally; `dev`/`build`
don't need a FIRMS key (that's only for `npm run fetch-firms`, passed as a
plain shell environment variable, not a `VITE_`-prefixed one, since it's only
read by the Node.js fetch script and never bundled into the frontend).

## Build output

### `dist/`

Production-ready static site, generated by `npm run build`:

```
dist/
├── index.html
├── assets/
│   ├── *.js
│   └── *.css
├── favicon.svg
└── data/
    └── (a copy of public/data/, including archive/)
```
